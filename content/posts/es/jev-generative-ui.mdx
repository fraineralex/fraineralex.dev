La mayoría de los productos de IA todavía coloca el modelo dentro de una ventana de chat fija. Eso funciona para responder preguntas, pero se queda corto en flujos de reservas, listas de soporte o paneles operativos que necesitan tarjetas, formularios, tablas y acciones.

La UI generativa permite que el modelo ayude a componer la interfaz. La versión útil no genera píxeles sin control ni React que nadie revisó. Selecciona componentes y acciones de un **catálogo** que tu equipo ya mantiene.

En este artículo veremos `json-render` de Vercel Labs, la combinación experimental con `jev`, el papel de AI Gateway y una pequeña demo interactiva.

## Chat fijo frente a UI generativa

```text
Chat fijo:      solicitud -> texto del LLM -> burbuja de chat
UI generativa:  solicitud -> elegir composición -> renderizar componentes aprobados
```

![Diagrama: chat fijo frente a UI generativa](/images/blog/posts/content/jev-diagram-1-es.webp)

La aplicación sigue siendo dueña de los componentes, el acceso a datos, los manejadores, la validación y los permisos. El catálogo le da al modelo espacio para componer sin entregarle el control del producto.

## Qué aporta json-render

[`json-render`](https://json-render.dev/) es un framework de UI generativa de Vercel Labs:

1. Defines un **catálogo** con componentes, acciones y propiedades de Zod.
2. El modelo genera una **especificación JSON** limitada a ese catálogo.
3. Tus componentes reales de React, o React Native, la renderizan.
4. **SpecStream** puede enviar parches JSONL para que la interfaz aparezca de forma progresiva.

![Diagrama: flujo de json-render](/images/blog/posts/content/jev-diagram-2-es.webp)

El catálogo es un límite del producto. La creatividad permanece dentro del sistema de diseño.

## Por qué las UI que generan árboles token a token pueden ser lentas

Una salida estructurada clásica le pide a un modelo grande que escriba un árbol JSON completo token a token. En una UI, ese árbol puede ser ancho y profundo, lo que retrasa la primera renderización útil.

El experimento público de Chris Tate combinó `json-render` con **jev** de TypeSafe AI, un modelo de decisiones estructuradas, mediante `experimental_composeSpec` y `experimental_createEvaluator`.

## Arquitectura con Vercel AI Gateway

```text
Cliente -> tu API (servidor) -> AI Gateway (typesafe-ai/jev) -> Spec -> React
```

![Diagrama: arquitectura con AI Gateway](/images/blog/posts/content/jev-diagram-4-es.webp)

```ts
import { experimental_createEvaluator } from "@json-render/core";

const evaluate = experimental_createEvaluator({
  apiKey: process.env.AI_GATEWAY_API_KEY!,
  model: "typesafe-ai/jev",
});
```

Trata las APIs `experimental_*` como versiones no publicadas y fija sus versiones. Confirma que Gateway permite TypeSafe AI en tu equipo. Valida cada Spec antes de renderizar y maneja los estados `finish`, `limit` y `unavailable`.

## Cuándo usar cada enfoque

![Diagrama: cuándo usar cada enfoque](/images/blog/posts/content/jev-diagram-5-es.webp)

| Enfoque | Úsalo cuando |
| --- | --- |
| Catálogo + jev / evaluator | Tienes un sistema de diseño y necesitas layouts dinámicos con límites claros |
| JSON estructurado con un LLM | Las Specs son pequeñas y la latencia es aceptable |
| Llamadas a herramientas | El modelo debe llamar APIs, no componer pantallas |
| Generación libre de código o píxeles | Solo estás explorando. Hay mucha libertad y también mucho riesgo |

## Lista antes de publicar

- Mantén `AI_GATEWAY_API_KEY` solo en el servidor.
- Confirma el acceso de Gateway a `typesafe-ai/jev`.
- Valida el catálogo y la Spec con Zod.
- Limita `maxElements`, `maxSteps` y `maxDepth`.
- Ofrece una interfaz fija como alternativa.
- Mide tu propia latencia y coste. No copies los tiempos de la demo.

La UI generativa no reemplaza la ingeniería frontend. Hace que la calidad del catálogo, las acciones y la validación sean todavía más importantes. El modelo se convierte en una capa entre la intención y las capacidades que ya publicaste.
